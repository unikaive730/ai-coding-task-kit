# 계획과 위임

## 나누는 기준
- 한 단위 = 실행해서 확인할 수 있는 결과 하나 (화면 하나, API 하나, 분석 표 하나)
- 30분이 넘어 보이면 더 나눈다
- 파일이 겹치지 않는 단위끼리만 나란히 진행한다

## docs/STATUS.md 형식
| 순서 | 단위 | 파일 | 완료 조건 | 상태 |
|---|---|---|---|---|

## 요청 틀 (사람이 에이전트에게, 에이전트가 하위 작업에게)
- 목표: 무엇을 만들거나 고치는지 한 줄
- 맥락: 관련 파일 · 데이터 · 오류 원문
- 제약: 건드리지 말 것 · 성능 · 형식
- 완료 조건: 어떤 명령을 돌려 무엇이 나오면 끝인지

## 순서
1. 데이터 읽기·점검 (이후 모든 단위의 바탕)
2. 핵심 기능 한 줄기를 끝까지 (입력 → 처리 → 출력)
3. 검증 · 문서
4. 남는 시간에 보조 기능

'구현 전부 끝내 줘'처럼 한 번에 맡기지 않는다. 고치는 데 시간이 더 든다.

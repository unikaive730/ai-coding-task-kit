# 검증과 제출 점검

## 기능을 끝낼 때마다
- 실행 명령과 출력 일부를 `docs/VERIFICATION.md` 에: 명령 · 기대 · 실제 · 판정
- 숫자 결과는 다른 계산(직접 합계, 표본 손계산, 다른 함수)으로 한 번 더 맞춘다
- 실패 원인은 한 줄로 적고 고친 커밋을 연결한다

## 제출 15분 전
1. 과제가 요구한 파일명 · 경로 · 실행 방법을 `docs/AGREEMENT.md` 표와 하나씩 대조
2. 서버가 `0.0.0.0` 으로 떠 있고 미리보기에서 핵심 동작이 되는지
3. 저장 안 된 파일 · 충돌 표시 없음
4. README: 실행 방법 · 구조 · 한계
5. `docs/DECISIONS.md` · `docs/STATUS.md` 가 실제 코드·`git log` 와 맞는지
6. 지어낸 값 · 예시 값이 결과물에 남아 있지 않은지
7. 마지막 커밋

## 후속 질문 대비 요약 (사람이 읽을 것, 5줄)
- 무엇을 왜 이렇게 만들었는지
- 가장 약한 곳과 그 영향
- 다음에 검증·개선할 것

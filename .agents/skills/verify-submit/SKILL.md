# 검증과 제출 점검

## 단위를 끝낼 때마다
- `docs/VERIFICATION.md` 한 줄: 대상 · 명령 · 기대 · 실제 · 판정
- 숫자 결과는 다른 계산(직접 합계 · 표본 한 건 손계산 · 다른 함수)으로 한 번 더 맞춘다
- 성공 기준 지표는 목표 값과 나란히 적는다 (예: 4/5건 · 목표 4건 이상 · 통과)
- 실패하면 원인 한 줄과 고친 커밋을 적는다

## 제출 15분 전 점검표
1. `docs/AGREEMENT.md` 과제 요구 표와 제출 파일명 · 경로 · 실행 방법을 하나씩 대조
2. README 의 실행 명령을 새 터미널에서 그대로 돌려 결과가 나오는지
3. 서버가 `0.0.0.0` 으로 떠 있고 미리보기에서 핵심 동작이 되는지
4. 에디터 저장 상태 '저장됨' · 충돌 표시 없음
5. README: 실행 한 줄 · 구조 · 성공 기준 결과 · 한계
6. `docs/DECISIONS.md` · `docs/STATUS.md` 가 실제 코드 · `git log` 와 맞는지
7. 지어낸 값 · 예시 값 · 쓰지 않는 틀 파일이 결과물에 남아 있지 않은지
8. 마지막 커밋 (사람이)

## 후속 질문 대비 요약 (사람이 읽을 것, 5줄)
- 문제와 성공 기준, 결과 숫자
- 가장 중요한 결정 두 개와 이유 · 버린 대안
- 가장 약한 곳과 그 영향
- 검증한 방법
- 시간이 더 있으면 할 것

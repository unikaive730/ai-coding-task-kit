# 문제 유형 판단

유형은 README 의 입력 · 출력 · 성공 숫자로 판단하고 근거를 `docs/AGREEMENT.md` 에 한 줄로 적는다. 지난 과제나 예시에 끌려가지 않는다. 아래는 빠뜨리기 쉬운 확인이고, 과제에 없는 줄은 건너뛴다.

- 경로·방문 순서: 출발·도착 고정 여부 · 왕복 여부 · 거리와 시간의 단위 · 머무는 시간 · 방문 가능 시간 · 이동·근무 상한 · 못 가는 곳 처리
- 배정·일정: 자격 · 겹침 · 인원 상한 · 공평성 · 빈 자리 처리 · 바뀐 뒤 다시 짜기
- 예측·분류: 시간 순 분할 · 미래 정보 누수 · 지표 정의 · 기준선 · 불균형 · 임계값 근거
- 이상 탐지·품질: 라벨 유무 · 오탐과 미탐의 비용 · 임계값 근거 · 설명 가능한 사유
- 데이터 분석·집계: 지표 정의 · 분모 · 기간 · 중복 · 다시 돌릴 수 있는 명령
- 웹·API·화면: 사용자 흐름 · 오류 응답 · 저장 · 동시 수정 · 재시작
- LLM·문서 검색·챗봇: 근거 · 지어내지 않기 · 출력 형식 · 실패 처리 · 평가 숫자
- 자동화·배치·CLI: 입력이 없을 때 · 다시 돌려도 같은 결과 · 부분 실패 · 종료 코드 · 로그
- 보고서·문서: 받는 사람 · 결론 · 숫자 출처 · 한계

어느 줄에도 안 맞으면 입력부터 출력까지 가장 단순한 형태를 먼저 끝까지 잇고, 결과를 바꾸는 값은 실무자에게 묻는다. 유형이 틀렸다는 근거가 나오면 AGREEMENT 와 계획을 고치고 DECISIONS 에 남긴다.

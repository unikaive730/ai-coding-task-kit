# 제약 최적화

1. 제약을 표로 나눈다: 반드시 지킬 것 · 되도록 지킬 것 · 목표 숫자. 파일에 없는 운영 제약은 실무자에게 묻는다
2. 지금 방식이나 가장 단순한 규칙으로 기준선 점수를 먼저 낸다
3. 제약 검사 함수를 해법과 따로 만든다. 입력은 해법 결과와 원본 데이터이고, 위반을 종류별 건수로 돌려준다
4. 해법은 단순한 순서로: 규칙 순서대로 넣기 → 교환·재배치 개선 → 그래도 목표에 못 미칠 때만 정확해. 패키지는 `docs/ENV.md` 에 있을 때만
5. 무거운 계산은 시간 상한을 둔다(AGENTS 의 상한). 같은 입력이면 같은 결과가 나오게 시드를 고정한다
6. 못 채운 건은 이유와 함께 출력한다(대상·날짜·막은 제약)
7. DECISIONS 방법 줄에 코드의 실제 단계 이름 · 처리 순서 기준 · 고르는 점수 · 멈춤 조건과 잰 초 · 버린 대안이 안 되는 이유(숫자)를 적는다
8. VERIFICATION 에 기준선 → 결과 숫자, 제약 위반 수, 몰린 날짜·대상 숫자를 적는다

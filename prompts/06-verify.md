- 탭 1 요청이 8번을 넘었으면 이 카드 전에 `/new` → '어디서 실행' 창이 뜨면 1(Use current Git worktree) → 빈 입력 칸이 보인 뒤 붙인다(대화가 길면 요청마다 앞 기록을 다시 읽어 토큰이 몇 배가 된다)

```
$verify-submit 목표: 한 줄 명령으로 결과물을 만들고 전체 테스트를 돌려 성공 기준을 검증해. 나란히 끝난 단위가 있으면 먼저 연결해.
제약: 성공 숫자는 평가 함수를 쓰지 않는 다른 계산(check_acceptance.py 가 있으면 고치지 말고 그것)으로 한 번 더 대조. 실패 경로 1~2개(잘못된 입력 거절 · 규칙 위반 거절과 그 응답 코드 · 저장 실패 · 같은 대상 동시 수정 두 건: 두 번째가 거절·덮어쓰기·이어 적용 가운데 무엇인지)도 실제로 돌려. 고칠 게 나오면 가장 작은 수정만 하고 처음 실패한 그 명령으로 다시 통과시켜. README·DECISIONS 는 다음 요청에서.
완료: VERIFICATION 에 명령·기대·실제·판정, STATUS 상태를 고치고 커밋. 답은 결과 숫자를 넣어 5줄 이내.
```

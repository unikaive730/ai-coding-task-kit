# 04 구현 단위 · STATUS 의 단위마다 한 번

```
목표: docs/STATUS.md <번호>번 단위를 구현해. 제약: 이 단위 파일만 고치고, 패키지는 docs/ENV.md 에 있고 DECISIONS 에 정한 것만(없으면 표준 라이브러리), 테스트는 핵심 3~5개(verify.py 에 더하는 검사는 100줄 안), 요구에 없는 기능은 만들지 마.
완료: STATUS 의 완료 조건을 실제로 돌려 통과하면 VERIFICATION 한 줄·STATUS 상태를 고친 뒤 커밋. 답은 정해진 5줄(바뀐 것 · 숫자 · 정한 것 · 확인 · 다음).
```

- 답을 받으면 사람이 결과 숫자를 직접 한 번 본다
- 기다리는 동안(2~6분) 사람이 할 것: ① 다음 단위의 숨은 제약·예외·경계값 질문 1~2개를 실무자 창에 보낸다(시간이 가장 많이 드는 일. 거리가 없으면 아직 안 물은 데이터 묶음(조·등급·구역·종류) 하나를 골라 실제 행 하나로 '○○인 사람·설비도 △△해도 되나요?', 묶음도 다 물었으면 last.sh 숫자로 사람별 나눔 '가장 많은 사람 ○회·적은 사람 ○회인데 괜찮나요?'. 답은 다음 요청 맨 앞에 '실무자 답: …' 한 줄로) ② 탭 2 검사 레인(05) 결과를 본다 ③ 다음 카드의 `<...>` 를 채워 둔다 ④ 터미널 탭 3(사람 셸)에서 `bash .agents/kit/last.sh`(지난 커밋 파일·새 결정 줄·검증 줄)로 이번 숫자 하나를 직접 본다(본 것은 CARDS.md 07 맥락 칸에 모아 두고, 숫자가 어긋날 때만 다음 요청 맨 앞에 '사람 확인: …' 한 줄) ⑤ 그래도 단위가 돌면 탭 3 에서 지난 커밋 파일의 함수 이름·상태 코드를 본다(`grep -n "def \|function \|40[0-9]" <파일>`) → last.sh 새 결정 줄 하나를 '무엇을·왜·버린 대안' 한 문장으로 말해 보고, 막히면 그 줄을 CARDS.md 에 적어 07 의 '왜?'로 묻는다(토큰 0). Codex 가 고치는 파일은 에디터로 열지 않는다(저장 충돌 창)
- 웹 과제는 화면 단위가 끝나면 사람이 새 탭에서 서버를 띄워 두고(닫지 않는다. README 에 실행 줄이 아직 없으면 `python3 app.py` 또는 `node server.js`) 브라우저로 필수 칸을 직접 본다

성공 지표가 목표에 못 미치면 06 전에 한 번 붙인다.

```
목표: <미달 지표>를 <목표>로 맞춰(<지킬 지표> 유지). 맥락: <명령> → <실제 숫자>.
제약: 고치기 전에 어디에 몰렸는지 숫자로 3줄. 그다음 규칙 하나만 가장 작게(설명 가능하게), 바꾼 기준은 docs/DECISIONS.md 한 줄. <다른 대화가 맡은 파일>은 건드리지 마.
완료: <명령>이 두 조건을 통과하면 VERIFICATION·STATUS 고치고 커밋. 같은 방법이 두 번 실패하면 멈추고 숫자로 보고. 답은 5줄.
```

구현 중에 Codex 가 실무자 확인을 묻고 커밋 없이 멈추면 이 블록.

```
실무자 답: <답>. docs/AGREEMENT.md·docs/DECISIONS.md 의 그 칸을 고치고 하던 단위를 마저 끝내 커밋해. 답은 5줄 이내.
```

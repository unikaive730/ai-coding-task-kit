# 04 구현 단위 · STATUS 의 단위마다 한 번

```
목표: docs/STATUS.md <번호>번 단위를 구현해. 제약: 이 단위 파일만 고치고(맨 앞에 붙인 실무자 답·탭 2 지적이 닿는 docs·코드·결과 파일은 다른 대화가 맡은 것이 아니면 같이 고치고 답에 그 파일 이름), 패키지는 docs/ENV.md 에 있고 DECISIONS 에 정한 것만(없으면 표준 라이브러리), 테스트는 핵심 3~5개(verify.py 에 더하는 검사는 100줄 안), 요구에 없는 기능과 README·실무자가 막으라고 하지 않은 거절(규칙 목록만 근거이거나 승인받은 한 경우를 넓힌 것 포함, 웹 409 · CLI 는 입력 파일·열 없음 밖의 멈춤)은 만들지 마(그런 위반은 받아 처리하고 경고). 파일 고침은 apply_patch, verify.py 는 혼자 한 명령으로.
완료: STATUS 의 완료 조건을 실제로 돌려 통과하면 VERIFICATION 한 줄·STATUS 상태를 고친 뒤 커밋. 답은 정해진 5줄(바뀐 것 · 숫자 · 정한 것 · 확인 · 다음). 있던 DECISIONS 줄과 다르게 구현하면 그 줄을 고쳐 옛 값과 그 이유 숫자는 버린 대안 칸 뒤에 덧붙이고(있던 대안·이유는 지우지 마), 정한 것에 '계획 ○ → 구현 ○'. 경로마다 방법이 다르면(예: 재편성만 정수계획) 같은 줄에 다른 경로에 그 방법을 안 쓴 이유(잰 숫자, 없으면 '비교 안 함'). 검사를 통과하려고 구현 값(상수·동점 규칙)을 바꿔 봤으면 그 결정의 이유 칸에 '바꿔 본 값 → 지표'.
```

- 답을 받으면 사람이 결과 숫자를 직접 한 번 본다
- 다음 단위를 붙이기 전, 앞 요청이 커밋됐고 마지막 `/new` 뒤 탭 1 에 보낸 글(실무자 답·조정·한 줄 답 포함)이 4번을 넘었으면 06 첫 줄대로 `/new` → 1 → Medium 확인 뒤 붙인다(커밋 없이 멈췄으면 하지 않는다)
- 기다리는 동안(2~6분) 사람이 할 것: ① 다음 단위의 숨은 제약·예외·경계값 질문 1~2개를 실무자 창에 보낸다(시간이 가장 많이 드는 일. 거리가 없으면 아직 안 물은 데이터 묶음(조·등급·구역·종류) 하나를 골라 실제 행 하나로 '○○인 사람·설비도 △△해도 되나요?', 묶음도 다 물었으면 last.sh 숫자로 사람별 나눔 '가장 많은 사람 ○회·적은 사람 ○회인데 괜찮나요?'. 답은 다음 요청 맨 앞에 '실무자 답: …' 한 줄로) ② 탭 2 검사 레인(05) 결과를 본다 ③ 다음 카드의 `<...>` 를 채워 둔다 ④ 터미널 탭 3(사람 셸)에서 `bash .agents/kit/last.sh`(지난 커밋 파일·새 결정 줄·검증 줄, 맨 위가 탭 2·5 커밋이면 `last.sh 3`)로 이번 숫자 하나를 직접 본다(본 것은 CARDS.md 07 맥락 칸에 모아 두고, 숫자가 어긋날 때만 다음 요청 맨 앞에 '사람 확인: …' 한 줄) ⑤ 그래도 단위가 돌면 탭 3 에서 지난 커밋 파일의 함수 이름·상태 코드를 본다(`grep -n "def \|function \|40[0-9]\|500\|BEGIN\|commit\|[Ll]ock" <파일>`) → last.sh 새 결정 줄 하나를 '무엇을·왜·버린 대안' 한 문장으로 말해 보고, 막히면 그 줄을 CARDS.md 에 적어 07 의 '왜?'로 묻는다(토큰 0). Codex 가 고치는 파일은 에디터로 열지 않는다(저장 충돌 창)
- 웹 과제는 화면 단위가 끝나면 사람이 새 탭에서 서버를 띄워 두고(닫지 않는다. README 에 실행 줄이 아직 없으면 `python3 app.py` 또는 `node server.js`) IDE 미리보기(터미널에 찍힌 포트)로 필수 칸을 직접 본다(브라우저 새 탭은 열지 않는다. 본 칸은 CARDS.md 07 맥락 칸에)

성공 지표가 목표에 못 미치면 06 전에 한 번 붙인다.

```
목표: <미달 지표>를 <목표>로 맞춰(<지킬 지표> 유지). 맥락: <명령> → <실제 숫자>.
제약: 고치기 전에 어디에 몰렸는지 숫자로 3줄. 그다음 규칙 하나만 가장 작게(설명 가능하게), 바꾼 기준은 docs/DECISIONS.md 한 줄. <다른 대화가 맡은 파일>은 건드리지 마. 파일 고침은 apply_patch, 검사 명령은 혼자 한 명령으로.
완료: <명령>이 두 조건을 통과하면 VERIFICATION·STATUS 고치고 커밋. 같은 방법이 두 번 실패하면 멈추고 숫자로 보고. 답은 5줄.
```

구현 중에 Codex 가 실무자 확인을 묻고 커밋 없이 멈추면 이 블록.

```
실무자 답: <답>. docs/AGREEMENT.md·docs/DECISIONS.md 의 그 칸을 고치고 하던 단위를 마저 끝내 커밋해. 답은 5줄 이내.
```

# 04 구현 단위 · STATUS 의 단위마다 한 번

```
목표: docs/STATUS.md <번호>번 단위를 구현해. 제약: 이 단위 파일만 고치고, 표준 라이브러리, 테스트는 핵심 3~5개, 요구에 없는 기능은 만들지 마.
완료: STATUS 의 완료 조건을 실제로 돌려 통과하면 핵심 숫자를 보이고, VERIFICATION 한 줄·STATUS 상태를 고친 뒤 커밋. 답은 5줄 이내.
```

- 답을 받으면 사람이 결과 숫자를 직접 한 번 본다
- 웹 과제는 화면 단위가 끝나면 사람이 새 탭에서 README 실행 한 줄로 서버를 띄워 두고(닫지 않는다) 브라우저로 필수 칸을 직접 본다

성공 지표가 목표에 못 미치면 06 전에 한 번 붙인다.

```
목표: <미달 지표>를 <목표>로 맞춰(<지킬 지표> 유지). 맥락: <명령> → <실제 숫자>.
제약: 고치기 전에 어디에 몰렸는지 숫자로 3줄. 그다음 규칙 하나만 가장 작게(설명 가능하게), 바꾼 기준은 docs/DECISIONS.md 한 줄. <다른 대화가 맡은 파일>은 건드리지 마.
완료: <명령>이 두 조건을 통과하면 VERIFICATION·STATUS 고치고 커밋. 같은 방법이 두 번 실패하면 멈추고 숫자로 보고. 답은 5줄.
```

구현 중에 Codex 가 실무자 확인을 묻고 커밋 없이 멈추면 이 블록.

```
실무자 답: <답>. docs/AGREEMENT.md·docs/DECISIONS.md 의 그 칸을 고치고 하던 단위를 마저 끝내 커밋해. 답은 5줄 이내.
```

# 10 설명 · 명령어·스킬·파일·카드 뜻 (외우지 않아도 된다. 잊으면 이 절을 본다)

사람이 외울 것은 없다. 긴 지시와 `$` 스킬은 카드 안에 이미 적혀 있어 복사해 붙이면 된다.

## 카드와 빈칸 뜻
- 카드: 이 파일의 번호 붙은 절. 그 안의 코드 블록(회색 칸)을 복사해 Codex 에 붙인다. 번호는 쓰는 순서다
- `<분>`·`<형식>`·`<번호>` 같은 `<...>` 칸은 안 채워도 된다. 그대로 붙이면 Codex 가 채운다. 사람이 넣는 것은 실무자 글뿐이다(카드 02)

## 문제와 푸는 방법을 설명받기 (토큰은 들지만 언제든 물어도 된다)
- 전체: `이 과제가 무슨 문제이고 어떻게 풀고 있는지 쉬운 말로 10줄로 설명해 줘. 고치지 말고`
- 한 부분: `<파일·함수·결정>은 무슨 일을 하고 왜 이렇게 했어? 쉬운 말로 5줄, 고치지 말고`
- 탭 1 이 쉴 때 탭 1 에 묻는다. 구현 중이면 + 로 새 터미널을 열어 `codex`(Medium 확인) 뒤 묻는다. 탭 2 는 구현을 읽지 않는 검사 대화라 묻지 않는다

## 터미널에 사람이 치는 것
- `codex` : 코딩 에이전트 시작. 탭마다 따로 띄운다
- `bash .agents/kit/last.sh` : 지난 커밋의 바뀐 파일·새 결정 줄·검증 줄 보기(토큰 0). `last.sh 3` 은 커밋 3개
- `git log --oneline` : 커밋 목록
- `du -sh .` : 제출 폴더 전체 크기. 제출 전에 한 번(10GB 이하)

## Codex 입력칸의 `/` 명령
- `/status` : 지금 모델·추론 수준·읽은 지침 파일 보기
- `/skills` : 쓸 수 있는 스킬 목록 보기. 12개가 보이면 된다
- `/model` : 모델·추론 수준 고르기. GPT-6.1-Sol → Medium
- `/new` : 새 대화. 파일·커밋은 그대로이고 대화 문맥만 비워 토큰이 준다. 창이 뜨면 1(Use current Git worktree). 추론이 기본으로 돌아가니 Medium 을 다시 본다

## `$` 스킬 (직접 칠 일은 거의 없다. 카드에 적혀 있다)
- `$interview-requirements` : 과제 파악. README·데이터로 요구 표를 채우고 실무자에게 보낼 질문을 만들고 받은 답을 반영한다(카드 01·02)
- `$plan-delegate` : 성공 기준이 정해진 뒤 일을 3~4개 단위로 나눠 계획을 적는다(카드 03)
- `$verify-submit` : 결과물을 연결해 검증하고 제출 직전 문서를 점검한다(카드 05·06·07)
- `$handoff` : 대화가 길어졌을 때 상태를 파일로 적어 새 대화로 넘긴다. 사람이 부를 때만(카드 09)
- `$kit-rules` : 작업 원칙 묶음. 과제에 자체 AGENTS.md 가 있어 `/status` 에 AGENTS.override.md 가 안 보일 때만 카드 01 맨 앞에 붙인다

## 상황이 맞으면 Codex 가 스스로 쓰는 스킬 (사람이 부르지 않아도 된다)
- `data-cleaning` : 데이터 정리·집계. 표기·빈 칸·중복·키 매칭을 숫자로 확인
- `optimize-schedule` : 배정·근무표·경로 같은 제약 최적화. 기준선과 제약 검사부터
- `web-api-build` : 웹·API·화면. 오류 응답·저장·동시 수정·재시작까지
- `llm-feature` : 모델 호출 기능. 키 처리·가짜 응답 시험·출력 형식 검사
- `report-output` : 보고서·표·그래프. 결론 먼저, 숫자는 결과 파일에서
- `debug-fix` : 오류·테스트 실패. 원인 가설 2개부터, 가장 작게 고침
- `metric-improve` : 지표가 목표에 못 미칠 때. 규칙 하나씩 고쳐 전후 숫자 남김
- `edge-cases` : 단위 마무리 때 경계값 점검

## 설치가 만드는 파일
- `docs/AGREEMENT.md` : 과제 요구·성공 기준·데이터 해석
- `docs/STATUS.md` : 단위 계획과 진행 상태
- `docs/DECISIONS.md` : 결정 · 정한 쪽 · 이유 · 버린 대안 표. 확인 질문 답의 재료
- `docs/VERIFICATION.md` : 실행한 명령 · 기대 · 실제 · 판정
- `docs/DATA_PROFILE.md` · `docs/ENV.md` : 설치 때 자동으로 만든 데이터 점검과 환경 점검
- `verify.py` : 구현 쪽 검사 · `check_acceptance.py` : 탭 2 가 요구 문서만 보고 만든 합격 검사
- `.agents/kit/CARDS.md` : 이 파일. 사람 메모도 여기에 적는다(제출물에 안 잡힌다)

## 승인 창과 단축키
- 승인 창: `commit.sh`·`verify.py`·`check_acceptance.py` 는 p(다시 묻지 않기) · 그 밖은 y · LLM·외부 주소는 esc 뒤 '가짜 응답으로 시험해'
- 터미널 붙여넣기 `Ctrl+Shift+V` · 터미널 복사는 글자를 선택한 뒤 `Ctrl+C`(선택 없이 누르면 실행 중인 codex·서버가 멈춘다) · 줄바꿈 `Alt+Enter`
- 파일 찾기 `Ctrl+P` · 내용 찾기 `Ctrl+Shift+F` · 탐색기 접기 `Ctrl+B`

## 실무자 창이 없으면
- 카드 01 끝의 '실무자 창이 없으면' 블록을 붙인다. 그 뒤 카드 02 와 카드의 실무자 질문·확인 단계는 건너뛴다
- 정한 값은 DECISIONS 표에 근거 숫자와 함께 남기고, README 와 데이터로 설명할 수 있게 읽어 둔다

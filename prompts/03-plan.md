# 03 계획 · 성공 기준이 숫자로 정해진 뒤

```
$plan-delegate 목표: docs/AGREEMENT.md 기준으로 단위 3~4개 계획을 docs/STATUS.md 에 적어. 남은 계산 세부 (추정)은 정해서 docs/DECISIONS.md 표에 한 줄씩, AGREEMENT 상태는 '확정'. 결과 숫자를 바꾸는 업무 규칙·제약 값이 아직 안 물은 (추정)이면 그 값은 (추정)으로 표시해 계획은 세우고 질문 3개 이하를 답에 같이 적어(성공 기준 숫자가 하나도 없을 때만 멈춰).
맥락: 남은 시간 <분>분, 제출물 <형식>. 제약: 시간은 일 크기대로(남은 시간을 채우지 마), 새 파일은 꼭 필요한 것만, 틀은 .agents/kit/templates/ 에서 복사, 성공 지표 계산 단위는 꼭, 보조 기능은 뒤로. 코드·HANDOFF 는 아직.
완료: 단위마다 파일·완료 조건(명령 → 기대), 나란히 단위 표시와 계약 10줄 이내, STATUS 40줄 이하가 되면 커밋. 답은 계획 4줄 · 실무자에게 보낼 기준 확인 한 메시지(DECISIONS 의 Codex 추정 가운데 결과 숫자를 가장 크게 바꾸고 아직 실무자가 답하지 않은 업무 값 2개 이하를 숫자로, '○○로 하려는데 괜찮을까요?'. 이미 답한 성공 기준·알고리즘·기술 선택은 넣지 말고, 그런 값이 없으면 '기준 확인 없음') · `정한 것:` 한 줄.
```

- 기준 확인 메시지와 질문은 실무자 창에 그대로 보내고, 답을 기다리지 않고 04 를 시작한다. 답은 02 카드로(04 를 시작했으면 다음 단위 요청 맨 앞에 '실무자 답: …'), 계획이 바뀌면 02 의 요구 변경 블록으로
- 계획이 커밋되면 탭 1 `/new` → 1(Use current Git worktree) → 아래 줄이 Medium 인지 보고(아니면 `/model`) 04 첫 단위를 붙인다(실무자 답·결정·계획은 docs 에 있다. 인터뷰 기록을 끌고 가면 단위마다 앞 기록을 다시 읽어 토큰이 두 배가 된다) · 같은 때 탭 2 에 05 첫 블록 · STATUS 에 나란히 단위가 있으면 탭 5 에도 05 의 탭 5 블록(화면 단위가 가장 오래 걸린다. 탭 1 첫 단위 앞에는 05 의 탭 1 한 줄)
- 성공 기준 숫자가 없어 멈췄으면 답을 02 로 넣은 뒤 이 카드를 다시 붙인다

# 02 인터뷰 정리 · 실무자 답을 받을 때마다

```
$interview-requirements 목표: 아래 실무자 답을 docs/AGREEMENT.md 에 반영해(누가 말했는지 표시).
제약: 바뀐 칸만 고치고 풀린 차이 줄은 지워. 인터뷰 기록은 질문당 한 줄, 원문은 옮기지 마(숫자·이름·상태 낱말(폐기 예정 등)은 그대로). 실무자가 정하지 않은 계산 세부와 처리가 안 정해진 답(정상이라 한 값 변화를 그대로 둘지·보정할지)은 우리가 정해 docs/DECISIONS.md 표에 한 줄씩. 코드는 아직. 답에 없는 내용은 (추정).
완료: 성공 기준이 숫자로 다 정해지고, 결과 숫자를 바꾸는 업무 규칙·제약 값(교체 시간·자격처럼 실무자만 아는 값. 이미 답한 규칙의 시작 시점·경계 같은 계산 세부는 묻지 말고 DECISIONS 에) 가운데 아직 안 물은 (추정)이 없으면 '확정'과 기준 2줄, 아니면 남은 것과 다음 질문(번호, 3개 이하, 지금 방식 숫자를 아직 못 받았으면 받는 사람을 바꿔 그 질문부터, 01 과 같은 꼴: 받는 사람 · 한 질문 한 주제 · 행·값을 넣은 예/아니요. '구체적으로'라는 답을 받은 질문은 후보마다 쪼개고, 01 에 이미 적은 질문은 번호만)을 답에 적고 끝에 `정한 것:` 한 줄. 커밋.
실무자 답: <메신저 답 붙여 넣기>
```

- 사람이 정한 값은 끝에 `우리 결정: <무엇 · 고른 값 · 근거>` 한 줄 · 질문을 그만하려면 끝에 `질문은 더 만들지 말고 남은 것은 정해서 docs/DECISIONS.md 에`
- 답이 돌거나 '모른다'면 같은 문장을 되풀이하지 말고 보기 2개('A면 …, B면 …인데 어느 쪽인가요?') → 데이터의 실제 행 하나 → '저는 ○○로 이해했는데 맞나요?' 순으로 바꿔 묻는다 · '정해진 것 없다'면 우리 안 하나를 제안하고, 승인이면 붙일 때 '담당자 승인(시각)'을 같이 적는다 · 실무자 답이 길면 숫자·조건이 든 문장만 붙인다 · 답이 3분 넘게 없으면 같은 질문을 한 번만 다시 보내고, 그래도 없으면 붙일 때 '담당자 무응답(시각)'

구현을 시작한 뒤 실무자가 요구를 바꿔 보내면 이 블록. 질문 답은 위 카드로 넣고, 03 은 다시 붙이지 않고 '다시' 단위부터 04.

```
$interview-requirements 목표: 아래 실무자 요구 변경을 반영해. AGREEMENT·DECISIONS 는 바뀐 칸만(옛 기준 숫자는 '변경 전'으로 한 줄 남겨), docs/STATUS.md 는 영향받는 단위만: 끝난 단위는 상태 칸을 '다시:' 뒤에 고칠 것 한 줄로, 새 일은 단위 한 줄, '나란히 계약'도 맞춰.
제약: 코드는 아직. 바뀐 기준의 목표 숫자를 모르면 그것이 질문 1번. 바뀐 값과 같은 숫자를 쓰던 간격·임계값은 추정하지 말고 질문에. 나란히 맡긴 대화가 있으면 거기 붙일 한 줄을 답에.
완료: 질문이 없으면 '확정'과 다시 할 단위 번호, 있으면 질문(번호, 3개 이하)을 답에 적어. 커밋.
실무자 변경: <메신저 글 그대로 붙여 넣기>
```

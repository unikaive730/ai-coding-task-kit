# 반도체 제조 데이터·AI 활용 과제 대비 요약

- 용도: 반도체 제조 데이터 과제에서 문제 정의·데이터 점검·접근법 선택을 빨리 하기 위한 요약
- 범위: 공개된 일반 지식과 분석 요령만 포함 · 특정 문제의 풀이와 특정 회사 내부 정보 없음
- 쓰는 순서: 5장 질문으로 문제 정의 → 2장으로 받은 데이터 열 대조 → 3장에서 과제 유형 선택 → 4장 점검표로 데이터 확인 → 6장 용어 확인
- 코딩 에이전트에 줄 때: 절 번호를 지정해 요청(예: "4장 점검표 기준으로 이 표 점검")
- 관리 한계·공정 능력 기준 등 수치는 관례 값 · 과제가 준 기준이 있으면 그 기준 우선

## 1. 메모리 반도체 공정 흐름

### 1.1 단계
전공정(FAB) → EDS(웨이퍼 테스트) → 패키징(packaging) → 최종 테스트(FT) → 출하

- 전공정(front-end, FAB)
  - 웨이퍼 위에 소자·배선 형성
  - 단위 공정: 산화(oxidation), 포토(photolithography), 식각(etch), 증착(deposition: CVD·PVD·ALD), 이온 주입(implant), 세정(cleaning), 평탄화(CMP), 금속 배선(metallization)
  - 같은 단위 공정이 층마다 반복 · 스텝 수가 많아 공정 이력 표가 길어짐
  - 중간중간 계측(metrology)·결함 검사(inspection)
  - 전공정 끝에 스크라이브 라인(scribe line) 테스트 패턴으로 전기 특성 측정(WAT·PCM, ET)
- EDS(electrical die sorting, 웨이퍼 테스트·프로브 테스트 probe test)
  - 프로브 카드(probe card)를 다이 패드에 대고 다이별 전기 검사
  - 온도 조건별 테스트(고온·저온), 웨이퍼 번인(wafer burn-in) 포함 가능
  - 메모리는 불량 셀을 여분 셀로 바꾸는 리페어(repair, redundancy) 단계 있음 · 리페어 전·후 결과 구분 필요
  - 결과: 다이별 빈(bin) 부여, 웨이퍼 맵 생성, 다이 수율 산출
- 패키징(back-end, assembly)
  - 웨이퍼 뒷면 연마(back grinding) → 다이 절단(sawing·dicing) → 기판 부착(die attach) → 연결(wire bonding 또는 flip chip·bump) → 몰딩(molding) → 마킹(marking)·볼 부착
  - EDS 양품 다이만 조립 · 웨이퍼 맵 정보로 조립 대상 선택
- 최종 테스트(FT, final test)
  - 패키지 상태 전기 검사, 번인(burn-in), 속도 등급 분류(speed binning) · DRAM 모듈 제품은 모듈 테스트(module test) 추가
- 추적성(traceability)
  - 패키지·유닛 ID에서 원래 로트·웨이퍼·다이 좌표까지 역추적 · 칩 안 퓨즈에 저장한 ID(ECID 등)를 쓰는 경우 많음
  - FT 불량을 EDS·전공정 데이터와 연결할 때 이 연결 표 필요

### 1.2 제품 구분
| 구분 | DRAM | NAND 플래시 | HBM |
|---|---|---|---|
| 기억 방식 | 커패시터 전하 · 셀 = 트랜지스터 1개 + 커패시터 1개(1T1C) | 전하 저장층(floating gate 또는 charge trap)에 전하 저장 | DRAM 다이 여러 장을 수직 적층 |
| 전원 끄면 | 내용 사라짐(휘발성) · 주기적 리프레시(refresh) 필요 | 내용 유지(비휘발성) | DRAM과 같음 |
| 구조 특징 | 셀 미세화, 커패시터 형성 | 셀을 여러 층으로 쌓는 3D NAND · 셀당 비트 수 SLC·MLC·TLC·QLC | TSV(through silicon via)로 다이 연결 · 맨 아래 베이스 다이(base die) · 인터포저(interposer) 위에서 프로세서와 연결 |
| 주요 품질 항목 | 동작 속도, 데이터 보존 시간(retention), 누설 전류 | 쓰기·지우기 반복 내구성(endurance, P/E cycle), 보존(retention), 비트 오류율(BER), 읽기 교란(read disturb) | 적층 전 양품 다이 선별(KGD), 적층 후 수율, 발열, 다이 간 신호 연결 |
| 대표 제품 | DDR(PC·서버), LPDDR(모바일), GDDR(그래픽) | SSD, 모바일 저장장치 | AI 가속기·GPU 메모리 |
| 분석 포인트 | 리페어 전후 수율, 리프레시 특성 불량 | ECC 전제, 불량 블록(bad block) 관리, 사이클 뒤 열화 | 다이 한 장 불량이 스택 전체 불량 · 다이 단위와 스택 단위 데이터 연결 |

### 1.3 데이터 단위
- 로트(lot): 함께 이동·처리되는 웨이퍼 묶음 · 보통 FOUP(웨이퍼 운반 용기) 하나, 최대 25장
- 웨이퍼(wafer): 메모리 양산은 지름 300mm가 일반적 · ID는 보통 로트 ID + 슬롯 번호(slot)
- 샷(shot): 노광 한 번에 찍히는 영역 · 샷 안에 다이 여러 개 · 샷 주기로 반복되는 불량은 마스크(reticle)·노광 쪽 후보
- 다이(die, chip): 웨이퍼 위 제품 한 개 · 좌표 (x, y) 또는 (row, col)
- 빈(bin): 테스트 결과 분류 코드
  - 하드 빈(hard bin): 양품·불량 대분류
  - 소프트 빈(soft bin): 불량 원인·테스트 항목별 세분
  - 빈 번호의 뜻은 제품·테스트 프로그램마다 다름 · 빈 정의표 먼저 확보
- 메모리 내부 단위: 비트(bit)·셀(cell)·워드라인(word line)·비트라인(bit line)·뱅크(bank)·블록(block) · 비트 단위 불량 위치 = 불량 비트 맵(fail bit map)
- 관계: 로트 1 : 웨이퍼 N : 다이 N · 로트 분할(split)·병합(merge)으로 관계가 바뀔 수 있음

## 2. 자주 나오는 데이터와 열 구성

- 열 이름은 예시(실제 과제의 열 정의서 우선) · 공통 조인 키: `lot_id`·`wafer_id`·`step_id`·`tool_id`·`chamber_id`·시각 열

### 2.1 수율(yield)·빈 맵
- 수율 종류
  - 라인 수율(line yield): 투입 웨이퍼 중 전공정을 끝까지 통과한 비율
  - 다이 수율(die yield, EDS yield): 웨이퍼의 양품 다이 수 / 전체 다이 수
  - 패키지 수율(FT yield): 양품 패키지 / 테스트 패키지
  - 누적 수율: 단계별 수율의 곱
- 대표 열: `lot_id, wafer_id, die_x, die_y, hard_bin, soft_bin, test_program, test_step(온도 조건), tester_id, probe_card_id, site_no, test_time, retest_flag`
- 확인할 것: 재테스트 행 처리(첫 결과 또는 마지막 결과), 리페어 전·후 구분, 가장자리 부분 다이 제외 여부, 수율 분모 정의

### 2.2 웨이퍼 맵(wafer map)
- 다이 좌표 + 빈 또는 합불 → 2차원 격자
- 패턴과 먼저 보는 원인 후보(가설일 뿐, 데이터로 확인 필요)

| 패턴 | 모양 | 먼저 보는 후보 |
|---|---|---|
| center | 중심부 불량 밀집 | 중심부 막 두께·식각 불균일, 척(chuck) 온도 분포, 가스 분사 |
| edge ring | 가장자리 고리 | 가장자리 증착·식각 불균일, 웨이퍼 가장자리(bevel) 오염, 가장자리 노광 |
| edge local | 가장자리 일부 구간 | 웨이퍼 고정 부품(clamp)·이송 접촉 위치, 노치 방향과 관련된 공정 |
| scratch | 가는 선 | 이송·취급 중 긁힘, CMP 긁힘 |
| cluster(local) | 한 곳에 덩어리 | 파티클·국부 오염, 국부 결함 |
| donut | 중심은 비고 중간 반경에 고리 | 반경 방향 불균일(회전 공정, 온도 구역 경계) |
| random | 전체에 흩어짐 | 무작위 파티클, 기본 불량 수준 |
| near full | 거의 전체 불량 | 큰 공정 사고, 테스트 장비·프로브 카드 문제 |

- 반복 패턴 구분
  - 샷 주기 반복: 마스크·노광 후보
  - 프로브 카드 접촉 단위(touchdown)·사이트(site) 번호별 반복: 테스트 쪽 후보 · `site_no`별 수율 비교
- 공개 데이터셋 WM-811K 분류 이름(Center·Donut·Edge-Loc·Edge-Ring·Loc·Near-full·Random·Scratch·none)을 그대로 쓰는 경우 많음
- 대표 열: `wafer_id, die_x, die_y, bin 또는 pass_fail` · 2차원 배열로 주는 경우도 있음

### 2.3 계측(metrology)
- 항목: 막 두께(thickness), 선폭(CD, critical dimension), 층간 정렬 오차(overlay), 면저항(Rs, sheet resistance), 단차·평탄도, 굴절률, 막 응력(stress)
- 표본 측정: 로트 중 일부 웨이퍼, 웨이퍼 중 일부 지점(site)만 측정 · 결측이 기본 상태
- 대표 열: `lot_id, wafer_id, step_id, item, site_id, site_x, site_y, value, unit, target, lsl, usl, tool_id, measure_time`
- 요약 방법: 웨이퍼별 평균·표준편차·범위, 중심 지점과 가장자리 지점 차이
- 전기 특성(WAT·PCM·ET): 문턱 전압(Vth), 포화 전류(Idsat), 저항, 누설 전류 · 공정 조건과 수율 사이의 중간 변수로 자주 사용

### 2.4 결함 검사(inspection·review)
- 검사(inspection): 광학·전자빔 장비로 웨이퍼 표면 결함 위치·크기 검출
- 리뷰(review): 검출 결함 일부를 SEM으로 촬영 · 자동 유형 분류(ADC, automatic defect classification): 파티클, 스크래치, 패턴 불량, 잔류물 등
- 대표 열: `lot_id, wafer_id, step_id, defect_id, x, y, size, defect_class, tool_id, inspect_time, image_path`
- 확인할 것
  - 단계 사이 새로 생긴 결함(adder) = 뒤 단계 결함 중 앞 단계에 같은 위치 결함이 없는 것
  - 결함 위치와 불량 다이 위치 겹침 → 결함 유형별 다이 불량 기여(kill ratio)
  - 검사 장비 좌표(mm, 중심 원점 등)와 다이 좌표 사이 변환식

### 2.5 장비 센서 시계열(FDC)
- FDC(fault detection and classification): 공정 중 장비 센서 값 수집·이상 감지 체계
- 센서 예: 온도, 압력, 가스 유량(MFC), RF 전력·반사 전력, 전압·전류, 식각 종료 감지 신호(endpoint, OES)
- 웨이퍼 한 장 처리 = 레시피 스텝(recipe step) 구간으로 나뉜 다변량 시계열
- 대표 열(긴 형식): `tool_id, chamber_id, lot_id, wafer_id, recipe_id, recipe_step, timestamp, sensor, value` · 넓은 형식이면 센서마다 열 하나
- 피처 만들기: 스텝별 평균·표준편차·최소·최대·기울기·구간 길이·안정화 시간
- 확인할 것: 센서마다 샘플링 주기 다름, 웨이퍼마다 길이 다름(스텝 기준으로 맞추거나 DTW로 정렬), 정상 범위가 레시피·챔버마다 다름

### 2.6 레시피·챔버
- 레시피(recipe): 장비에 내리는 공정 조건 묶음(시간·온도·압력·가스·전력) · 버전 변경 이력 있음
- 장비(tool) 하나에 챔버(chamber) 여러 개 · 같은 장비 안에서도 챔버 사이 결과 차이(chamber matching 문제)
- 대표 열: `tool_id, chamber_id, recipe_id, recipe_version, param, value, changed_at`
- 확인할 것: 원인 분석은 챔버 단위까지 내려가 비교, 레시피 변경 시점 앞뒤 비교

### 2.7 공정 이력(route·step)
- 라우트(route, flow): 제품이 거치는 스텝 순서 목록
- 스텝(step, operation): 공정 단계 하나 · 스텝마다 장비·챔버·레시피 선택
- 로트 이력(lot history): 언제·어느 스텝을·어느 장비·챔버·레시피로 처리했는지 기록
- 대표 열: `lot_id, wafer_id, step_seq, step_id, step_name, tool_id, chamber_id, recipe_id, track_in, track_out, rework_flag, hold_flag`
- 확인할 것
  - 공통성 분석의 기본 표
  - 로트 단위 기록과 웨이퍼 단위 기록 구분 · 같은 로트의 웨이퍼가 다른 챔버를 거칠 수 있음
  - 재작업(rework)·보류(hold)·건너뛴 스텝 표시, `step_seq` 기준 정렬

### 2.8 설비 가동(OEE·PM)
- 장비 상태(SEMI E10 분류 예): 생산(productive), 대기(standby), 엔지니어링(engineering), 계획 정지(scheduled down, PM 포함), 비계획 정지(unscheduled down, 고장), 미가동(non-scheduled)
- OEE(overall equipment effectiveness) = 가용률(availability) × 성능률(performance) × 양품률(quality)
- PM(preventive maintenance): 주기 정비 · 정비 뒤 챔버 안정화(seasoning)와 시험 웨이퍼 확인(qualification) · 관련 지표 MTBF(평균 고장 간격)·MTTR(평균 수리 시간)
- 대표 열: `tool_id, chamber_id, state, start_time, end_time, reason_code, pm_type, part`
- 확인할 것: 상태 구간 겹침·빈 구간, PM 뒤 경과 시간·누적 처리 매수·RF 누적 시간을 피처로 사용, PM 직후와 직전 품질 비교

### 2.9 WIP·사이클 타임
- WIP(work in process): 공정 중인 재공 로트·웨이퍼 수
- 사이클 타임(cycle time): 투입부터 출하까지 시간 · 스텝별로는 대기(queue) + 처리(process) + 이동(transport)
- X-factor: 사이클 타임 / 순수 처리 시간
- 리틀의 법칙(Little's law): 평균 WIP = 평균 처리량 × 평균 사이클 타임(안정 상태 가정)
- 대표 열: `lot_id, product, step_id, queue_in, track_in, track_out, priority, due_date, wafer_qty`
- 운영 제약
  - Q-time(queue time limit): 앞 스텝 뒤 정해진 시간 안에 다음 스텝을 시작해야 하는 제약
  - 배치 장비(batch tool): 여러 로트를 한 번에 처리(확산로 furnace 등)
  - 장비 전용(dedication)·장비 자격(qualification): 특정 제품·스텝을 특정 장비만 처리
  - 셋업 전환(setup change): 레시피·마스크 교체 시간

### 2.10 품질 SPC
- 관리도(control chart) 종류
  - 연속값: X-bar·R, X-bar·S, 개별값 I-MR
  - 불량률: p, np · 결함 수: c, u
  - 작은 이동 감지: EWMA, CUSUM
- 관리 한계(UCL·LCL)와 스펙 한계(USL·LSL) 구분
  - 관리 한계: 공정 자체 변동 기준 · 보통 중심선 ± 3σ
  - 스펙 한계: 설계·고객 요구 기준
- 공정 능력 지수
  - Cp = (USL - LSL) / 6σ: 산포만 반영
  - Cpk = min(USL - μ, μ - LSL) / 3σ: 중심 치우침까지 반영
  - Pp·Ppk: 군내 σ 대신 전체 표준편차 사용
  - 1.33 이상을 양호로 보는 관례가 많음 · 과제 기준 우선
- Western Electric 규칙(중심선 기준 σ 구역, 확장판은 Nelson 규칙: 연속 6점 증가 또는 감소 등)
  1. 1점이 3σ 밖
  2. 연속 3점 중 2점이 같은 쪽 2σ 밖
  3. 연속 5점 중 4점이 같은 쪽 1σ 밖
  4. 연속 8점이 중심선 같은 쪽
- 대표 열: `chart_id, item, step_id, tool_id, sample_time, value, cl, ucl, lcl, usl, lsl, ooc_flag, rule_id`
- 확인할 것: 규칙을 많이 켤수록 거짓 경보 증가, 관리 한계 계산 기간 정의, 정규 분포 가정 확인, 군(subgroup) 구성 단위(웨이퍼·로트)

## 3. 과제 유형별 분석·AI 요령

공통 순서: 기준 모델(baseline) 먼저 → 평가 지표 고정 → 개선 모델 → 실무자 확인

### 3.1 이상 탐지(anomaly detection)
- 기본 접근
  - 정상 기준을 레시피·챔버·제품별로 따로 정의
  - 단변량: 관리도, z-score, IQR · 다변량: PCA 기반 T²·SPE(Q), 마할라노비스 거리
  - 모델: Isolation Forest, One-class SVM, 오토인코더 재구성 오차 · 센서 시계열은 스텝별 요약 피처로 바꾼 뒤 적용
  - 경보마다 기여한 센서·스텝 표시(contribution)
- 기준 모델: 레시피 스텝별 평균 ± 3σ 규칙
- 평가 지표: 라벨 있으면 정밀도·재현율·F1·PR-AUC, 탐지 지연(detection delay), 하루 경보 수
- 흔한 함정
  - 학습용 정상 데이터에 이상이 섞임
  - PM 뒤 정상 범위 이동을 이상으로 판정
  - 실무자가 처리할 수 없을 만큼 많은 경보
  - 라벨이 적어 성능 근거 없음 · 알려진 이상 사례 몇 건으로라도 확인

### 3.2 수율 저하 원인 분석(commonality·장비/챔버별 비교)
- 기본 접근
  - 불량 집합과 정상 집합 정의(수율 기준선, 기간)
  - 공통성 분석: 스텝마다 장비·챔버·레시피별 불량 비율 비교 · 카이제곱·피셔 정확 검정, 수율 차이는 t검정·Kruskal-Wallis
  - 시간 축: 수율 하락 시작 시점 앞뒤로 바뀐 것(PM, 레시피 변경, 소재 로트 변경, 새 장비 투입)
  - 연속 변수(계측·WAT·FDC 요약)와 수율: 상관, 트리 모델(랜덤 포레스트·그래디언트 부스팅) 중요도, SHAP
  - 웨이퍼 맵 패턴을 같이 보고 후보 공정 좁히기
- 기준 모델: 스텝 × 장비(챔버) 교차표의 불량 비율 순위
- 평가 지표: 실무자 확인 기준 상위 k개 후보 안 정답 포함 여부, 후보 수 축소 정도 · 예측 모델이면 AUC
- 흔한 함정
  - 여러 번 검정해 우연히 유의한 결과(다중 비교) · Bonferroni·FDR 보정
  - 교란(confounding): 특정 제품만 특정 장비로 처리돼 장비 효과와 제품 효과가 섞임
  - 처리 매수가 적은 장비가 비율 상위에 옴 · 표본 수 같이 표시
  - 상관을 원인으로 단정
  - 로트 단위 집계와 웨이퍼 단위 집계 혼동

### 3.3 웨이퍼 맵 패턴 분류
- 기본 접근
  - 맵을 고정 크기 격자로 변환 · 웨이퍼 밖 영역은 별도 값
  - 수작업 피처: 반경 구간별 불량 밀도, 각도 구간별 밀도, 연결 성분(connected component) 크기, 선형성, Radon 변환
  - 모델: 피처 + 트리·SVM, 작은 CNN, 사전학습 모델 미세조정 · 여러 패턴이 겹친 맵은 다중 라벨
  - 라벨이 적으면 클러스터링(k-means·DBSCAN)으로 묶은 뒤 묶음 단위 라벨
- 기준 모델: 반경·각도 밀도 피처 + 로지스틱 회귀 또는 랜덤 포레스트
- 평가 지표: 클래스별 재현율, macro-F1, 혼동 행렬
- 흔한 함정
  - none 클래스가 대부분이라 정확도만 높게 나옴
  - 회전·뒤집기 증강이 노치 기준 위치 정보를 지움(edge local 등)
  - 다이 수·맵 크기가 다른 제품이 섞임
  - 같은 로트 웨이퍼가 학습·평가 양쪽에 들어감

### 3.4 시계열 예측(forecasting)
- 대상: 수율 추이, WIP·출하량, 장비 고장·정비 시점(잔여 수명 RUL), 계측값 이동(drift), 소모품 교체 시점
- 기본 접근
  - 예측 단위·주기·예측 기간(horizon) 먼저 고정
  - 통계 모델: ETS, ARIMA·SARIMA, Prophet
  - 머신러닝: 지연값(lag)·이동 통계·달력 피처 + 그래디언트 부스팅
  - 검증: 시간 순서를 지킨 롤링 검증(rolling origin, TimeSeriesSplit)
  - 같은 틀의 회귀 과제: 가상 계측(virtual metrology, FDC 요약값으로 계측값 추정)
- 기준 모델: 직전 값(naive), 직전 주기 같은 시점 값(seasonal naive), 이동평균
- 평가 지표: MAE, RMSE, MAPE(0 근처 값이 있으면 sMAPE·MASE), 구간 예측이면 포함률(coverage)
- 흔한 함정
  - 무작위 분할로 미래 정보가 학습에 들어감
  - 공정 변경 시점 앞뒤 분포 차이 무시
  - 집계 기준 시각(교대 shift, 일 경계) 불일치
  - 데이터 없는 기간을 0으로 채움

### 3.5 일정·배치 최적화(scheduling·dispatching)
- 대상: 로트 처리 순서(dispatching), 배치 장비 묶기, 장비 배정, PM 일정, 프로브 카드·마스크 배정
- 기본 접근
  - 목표 함수 하나 고정(납기 지연 합, 사이클 타임, 처리량, 장비 가동률) + 제약 목록(Q-time, 장비 자격, 배치 크기, 셋업 전환)
  - 정수계획(MILP: OR-Tools·PuLP), 제약 프로그래밍(OR-Tools CP-SAT)
  - 문제가 크면 휴리스틱(유전 알고리즘·시뮬레이티드 어닐링·탭 탐색)
  - 이산 사건 시뮬레이션(discrete event simulation)으로 규칙끼리 비교
- 기준 모델: 처리 순서 규칙 FIFO, EDD(납기 빠른 순), SPT(처리 시간 짧은 순), CR(critical ratio)
- 평가 지표: 기준 대비 목표 함수 개선률, 제약 위반 0건, 계산 시간(운영 주기 안에 끝나는지)
- 흔한 함정
  - 제약 누락으로 실행할 수 없는 일정
  - 문제 크기가 커져 MILP 시간 초과 · 시간 제한과 근사해 허용
  - 장비 고장·재작업 같은 변동 무시
  - 지표 하나만 좋아지고 다른 지표 악화 · 보조 지표 같이 보고

### 3.6 LLM 활용 업무 자동화(문서·로그 요약 등)
- 대상: 장비 알람·이벤트 로그 요약, 교대 인수인계 보고, 불량 분석 보고서 초안, SOP·매뉴얼 검색, 정비 기록 자유 서술 분류, 자연어 질문 → SQL
- 기본 접근
  - 입력·출력 형식 먼저 정의(JSON 스키마, 보고서 항목)
  - 규칙으로 되는 부분(파싱·집계·필터)은 코드, 요약·분류·서술만 LLM
  - 긴 로그는 중복 알람 묶기·시간 구간 집계로 줄인 뒤 입력
  - 문서 검색은 RAG(retrieval augmented generation): 문서 조각(chunk) + 임베딩 검색 + 출처 표시
  - 숫자는 코드로 계산한 값을 넣고 LLM에 계산을 맡기지 않음
- 기준 모델: 템플릿 + 규칙 요약(상위 알람 빈도표, 시간대별 건수)
- 평가 지표: 표본 사람 채점(정확성·누락·쓸모), 분류면 정확도·F1, 출처 일치율, 작업 시간 단축
- 흔한 함정
  - 없는 장비 ID·수치 생성(환각, hallucination) · 출력의 ID·숫자를 원본과 대조하는 검증 단계 필수
  - 사내 데이터를 외부 API로 전송 · 허용 범위 먼저 확인
  - 입력 길이 초과로 뒷부분 누락
  - 평가 없이 시연만 준비

### 3.7 대시보드
- 대상: 수율 추이, 장비 상태, WIP, SPC 경보, 이상 탐지 결과
- 기본 접근
  - 보는 사람과 그 사람이 내릴 결정 하나 먼저 정의
  - 화면 위에서 아래로: 핵심 지표 → 추이 → 세부(로트 → 웨이퍼 → 다이 순 drill-down)
  - 필터: 기간·제품·스텝·장비·챔버
  - 그래프에 관리 한계·스펙 한계·목표선 같이 표시
  - 도구: Streamlit, Dash, Plotly
- 기준 모델: 핵심 지표 표 + 추이 그래프 1장
- 평가 지표: 실무 질문 하나에 답하는 데 걸리는 시간·클릭 수, 데이터 갱신 지연, 실무자 확인
- 흔한 함정
  - 지표 정의(분자·분모) 미표시
  - 그래프가 너무 많아 핵심 지표를 찾기 어려움
  - 데이터 기준 시각 미표시
  - 웨이퍼 맵 y축 방향·노치 방향 뒤집힘

## 5. 문제 정의 질문 목록

실무자(업무 담당자 에이전트)에게 처음 묻는 질문

1. 결과를 보고 누가 어떤 결정·행동을 하는지(의사결정자)
2. 지금은 그 일을 어떻게 하고 있고, 시간이 얼마나 걸리는지(현재 방식)
3. 개선할 지표 하나와 지금 값(목표 지표·기준선)
4. 어떤 값이 나오면 쓸 수 있다고 판정하는지(성공 기준)
5. 결과물 형태: 보고서·점수표·경보 목록·대시보드·스크립트·API 중 무엇인지
6. 데이터 범위: 기간·제품·스텝·장비, 행 수, 갱신 주기
7. 각 표의 열 뜻·단위와 표 사이 조인 키
8. 라벨(불량·이상) 유무, 판정 기준, 라벨을 붙인 사람
9. 판단 시점에 실제로 알 수 있는 정보의 범위(누수 방지)
10. 놓침(미탐)과 거짓 경보 중 더 큰 손해
11. 제약: 실행 시간, 처리 주기(실시간·일 단위), 설명 필요 여부, 쓸 수 있는 환경·라이브러리
12. 이미 알려진 원인·가설과 이미 시도해 실패한 방법
13. 분석에서 뺄 데이터(엔지니어링 로트, 재작업, 특정 제품)
14. 결과 검증 담당과 검증 방법
15. 정확도·설명 가능성·속도 중 우선순위

문제 정의 정리 양식

```
목적: [누가] [어떤 결정·행동]
입력: [데이터 범위·표 이름]
출력: [결과물 형태]
성공 기준: [지표] [목표 값] 이상 (기준 모델 [값])
제약: [실행 시간·환경·설명 필요 여부]
제외: [뺄 데이터]
```

## 6. 용어 사전

| 용어 | 뜻 |
|---|---|
| FAB(전공정) | 웨이퍼 위에 회로를 만드는 공정 전체와 그 공장 |
| EDS(electrical die sorting) | 웨이퍼 상태에서 다이별 전기 검사·양불 분류 |
| FT(final test) | 패키지 상태 최종 전기 검사 |
| WAT·PCM | 스크라이브 라인 테스트 패턴의 전기 특성 측정 |
| 프로브 카드(probe card) | EDS에서 다이 패드에 접촉하는 바늘 묶음 부품 |
| 빈(bin) | 테스트 결과 분류 코드(하드 빈·소프트 빈) |
| 웨이퍼 맵(wafer map) | 다이 좌표별 빈·합불을 그린 2차원 그림 |
| 로트(lot) | 함께 처리되는 웨이퍼 묶음 |
| 라우트(route) | 제품이 거치는 스텝 순서 |
| 레시피(recipe) | 장비에 내리는 공정 조건 묶음 |
| 챔버(chamber) | 장비 안 웨이퍼 처리 공간 |
| FDC | 장비 센서 데이터로 공정 이상 감지·분류 |
| 계측(metrology) | 두께·선폭·정렬 오차 등 측정 |
| 오버레이(overlay) | 위아래 층 패턴 정렬 오차 |
| 결함 검사(inspection) | 웨이퍼 표면 결함 위치 검출 |
| ADC | 결함 이미지 자동 유형 분류 |
| adder | 두 검사 단계 사이에 새로 생긴 결함 |
| SPC | 관리도 기반 통계적 공정 관리 |
| UCL·LCL | 관리 상한·하한(공정 변동 기준) |
| USL·LSL | 스펙 상한·하한(요구 기준) |
| Cp·Cpk | 스펙 대비 공정 산포·치우침 지수 |
| OOC(out of control) | 관리 규칙 위반 상태 |
| OEE | 가용률 × 성능률 × 양품률 |
| PM(preventive maintenance) | 주기 정비 |
| WIP | 공정 중인 재공 |
| 사이클 타임(cycle time) | 투입부터 출하까지 시간 |
| Q-time | 스텝 사이 최대 허용 대기 시간 |
| 디스패칭(dispatching) | 장비 앞 대기 로트 중 다음 처리 로트 선택 |
| 재작업(rework) | 공정 결과를 제거하고 다시 처리 |
| 리페어(repair) | 불량 셀을 여분 셀로 대체 |
| 번인(burn-in) | 고온·고전압 스트레스로 초기 불량 선별 |
| TSV(through silicon via) | 실리콘을 관통하는 수직 전극 |
| KGD(known good die) | 적층·조립 전 양품 확인 다이 |
| APC·R2R(run-to-run) | 앞 결과로 다음 공정 조건 자동 보정 |
